# ตรวจเครื่องบิน การซูม และข้อมูลแผนที่

รายงานนี้ต่อจาก [การตรวจระบบเดิม](bug-audit.md) และอธิบายการแก้รอบเครื่องบิน/ซูมประเทศ โดยคงหน้าแรกเป็นลูกโลก MozzieMap และคง `/simulator` กับ `/sent-scent`

## ปัญหาและการแก้

| ปัญหาที่ตรวจพบ | สาเหตุ | พฤติกรรมหลังแก้ |
| --- | --- | --- |
| เครื่องบินหายเมื่อ WebGL ถูกปิด | software globe ยังไม่มีชั้นวาดเที่ยวบิน | ทั้งสอง renderer มีเครื่องบินและเส้นทางบิน กล้องติดตามเส้นทางก่อนซูมเข้าประเทศ |
| เลือกประเทศแล้วซูมไม่ถึงพื้นที่ | กล้อง GPU ใช้ altitude 1.5 ทุกประเทศ ส่วน software เปลี่ยนเฉพาะมุม | คำนวณระยะกล้องจากขนาดประเทศและพื้นที่หน้าจอที่ใช้ดูแผนที่ |
| ประเทศที่เลือกหลุดจากจอเมื่อซูม | ชดเชย longitude/latitude เพื่อหลบ panel โดยไม่สัมพันธ์กับระยะกล้อง | แยกพื้นที่แผนที่กับรายละเอียดและเล็งกลางประเทศโดยตรง |
| เลือกประเทศระหว่าง GPU โหลดแล้วเที่ยวบินค้าง | รับคำสั่งทั้งที่ตัวแสดงผลยังไม่พร้อม | รอ renderer พร้อมก่อนเปิดให้เลือกประเทศ และทดสอบด้วยการหน่วง texture จริง |
| ประเทศกว้างถูกตัดบนแท็บเล็ตแนวตั้ง | จำกัดระยะกล้องไว้ที่ 2.2 แม้พื้นที่แผนที่แคบ | คำนวณตาม aspect และขยายระยะได้ถึงขอบเขตเดิมของ controls พร้อมตรวจ perspective ทุกประเทศ |
| มือถือดูแผนที่ต่อไม่ได้ | รายละเอียดสูงเต็มหน้าจอ | รายละเอียดอยู่ครึ่งล่าง ลูกโลกครึ่งบนยังลาก/ซูมได้ และเนื้อหารายละเอียดเลื่อนอ่านได้ |
| ท่าทางสองนิ้วหมุนแทนซูม | software จัดการ pointer เดียว | ติดตาม pointer สองจุดและใช้ระยะห่างเพื่อ pinch zoom พร้อมปุ่ม +/− และรีเซ็ตทั้งสอง renderer |
| ลูกโลกหมุนต่อหลังผู้ใช้หยุด autopilot | effect/hover/close เปิด autoRotate กลับ | การโต้ตอบหยุดเที่ยวบินและการหมุน ไม่แย่งการควบคุมจากผู้ใช้ |
| เครื่องบินหันกลับด้าน | `lookAt` ชี้ +Z แต่จมูกโมเดลชี้ −Z | หันโมเดลให้จมูกตรงทิศบิน |
| เลโซโทถูกสีแอฟริกาใต้ทับ | การโหลด GeoJSON ตัด interior rings ออก | เก็บทุก ring ทำให้ enclave และขอบเขตการเลือกตรงกับข้อมูลต้นฉบับ |
| สถิติกราฟและแถบยุงทับกันบนแท็บเล็ต | breakpoint อิงหน้าจอ แต่ panel แคบกว่าหน้าจอมาก | จำนวนคอลัมน์อิงความกว้างกราฟจริง และแถบเลือกยุงย่อให้พอดีกับพื้นที่แผนที่ |
| ไฮไลต์กราฟคลิกแล้วไม่ค้าง | hover/focus เปลี่ยน state เดียวกับ click toggle | แยก preview กับการเลือกค้าง คลิกซ้ำล้างได้และใช้คีย์บอร์ดได้ |

การเปลี่ยนประเทศหรือชนิดยุง การเริ่มลาก/ซูม และการสูญเสีย GPU context ยกเลิกเที่ยวบินเก่า ใช้หมายเลขเที่ยวบินตรวจตอนจบเพื่อไม่ให้คำสั่งเก่าเปิดรายละเอียดประเทศผิดหลังผู้ใช้เปลี่ยนใจ ทรัพยากร Three ที่สร้างสำหรับเส้นทางถูกถอดและ dispose เมื่อจบหรือยกเลิก

## ความถูกต้องทางภูมิศาสตร์

การบินใช้เส้นโค้งบนทรงกลมและข้ามเส้นวันที่สากลทางสั้น รองรับจุดตรงข้ามกันและบริเวณขั้วโลก การจัดกรอบเริ่มจากผืนแผ่นดินที่ใหญ่ที่สุด แล้วรวมเกาะของประเทศเดียวกันที่มีศูนย์กลางอยู่ภายใน 45 องศาบนทรงกลม วิธีนี้แสดงหมู่เกาะฟิจิ อินโดนีเซีย ญี่ปุ่น และนิวซีแลนด์ครบจากชุดข้อมูล ขณะที่ฝรั่งเศสยังเน้นยุโรปแทนการถอยกล้องไปรวม French Guiana

เกณฑ์นี้เป็นวิธีจัดกล้อง ไม่ได้เปลี่ยนพรมแดน อธิปไตย หรือข้อมูลต้นฉบับ ผู้ใช้ยังหมุนลูกโลกไปดูดินแดนที่อยู่ไกลได้ รูปขอบเขตมาจาก GeoJSON เดิมที่มี 177 features จึงมีความละเอียดจำกัดเมื่อซูมมาก ไม่ได้เพิ่มรายละเอียดถนนหรืออาคาร

## ข้อมูลและการเก็บข้อมูลผู้ใช้

ตรวจทั้ง 177 ประเทศและยุงทั้งสามกลุ่ม คะแนนอยู่ในช่วง 0–10 แผนที่/รายละเอียดใช้คะแนนเดียวกัน ประวัติรายวันมี seed คงที่ ประเทศที่คะแนนศูนย์ยังมีจำนวนจำลองเป็นศูนย์ การเปลี่ยนประเทศกลับไปมาไม่สร้างชุดตัวเลขสุ่มใหม่

คะแนน hotspot และจำนวนรายวันยังเป็น **ข้อมูลจำลอง** ไม่ใช่ยอดผู้ป่วยจริงหรือผลพยากรณ์ ลิงก์ WHO/CDC เป็นข้อมูลโรคพื้นฐาน ไม่ใช่ที่มาของตัวเลขในกราฟ ประชากรเป็นค่าประมาณปี 2013/2014/2017 ตามข้อมูลเดิม และหน้ารายละเอียดแสดงปีไว้ การตรวจความสอดคล้องของโปรแกรมไม่ได้เปลี่ยนข้อมูลจำลองให้เป็นข้อมูลเฝ้าระวังที่ผ่านการรับรอง

รอบนี้ไม่เปลี่ยน schema ไม่ย้ายฐานข้อมูล ไม่ล้าง cookies/localStorage/IndexedDB และไม่ลบ CacheStorage การทดสอบ service worker ใช้ profile ชั่วคราว ใส่ draft ใน localStorage กับ cache ของแอปอื่นก่อนอัปเดต แล้วตรวจว่าข้อมูลยังอยู่และเปิดลูกโลก offline ได้ ไม่มีการเปิดหรือล้าง profile จริงของผู้ใช้

## การทำซ้ำและหลักฐาน

เริ่ม production server ที่ port 3001 แล้วรัน:

```bash
npm test
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
CHROMIUM_PATH=/usr/bin/chromium npm run test:navigation
CHROMIUM_PATH=/usr/bin/chromium npm run test:tablet
```

`test:navigation` ตรวจเครื่องบินจากภาพ canvas จริง เปรียบเทียบ pixels หลังปุ่มซูม/ล้อเมาส์/pinch ตรวจกรอบ Belgium เทียบ Brazil ทดลองยกเลิกและเปลี่ยนเที่ยวบินอย่างรวดเร็ว ตรวจกล้องไม่หมุนต่อเองหลังซูม และตรวจปุ่มรีเซ็ตทั้ง WebGL/software

`test:tablet` ใช้ viewport 768×1024 ตรวจ Russia/Canada ข้างรายละเอียดจาก WebGL จริง โดยตรวจทั้งระยะกล้องและ pixels ของประเทศที่เลือกว่ามองเห็นและไม่ล้นขอบ

ชุด smoke ตรวจการลาก/เลือกประเทศ ชนิดยุงและกราฟ รวมการเลือก legend แบบค้างและ preview การสูญเสีย context การ retry ข้อมูล มือถือ SENT SCENT และ offline/user storage ผลภาพและ JSON ของแต่ละรอบอยู่ใน directory ที่กำหนดด้วย `QA_ARTIFACTS` โดย browser tests ใช้ profile ทิ้งได้แยกจากบัญชีผู้ใช้

ตัวอย่างหลักฐาน: ภาพ Russia บนแท็บเล็ตมี selected-land pixels 16,411 จุด โดยไม่มี selected-land pixel ที่ขอบ viewport ส่วน Canada มี 18,017 จุดและไม่มีที่ขอบเช่นกัน ล้อเมาส์และ pinch เปลี่ยนภาพจริงทั้งสอง renderer ไม่ได้ตรวจเพียงว่ามี canvas หรือข้อความสถานะ

การทดสอบบน Chromium/SwiftShader ไม่ครอบคลุม driver และนโยบาย GPU ทุกเครื่อง จึงไม่ถือเป็นหลักประกันว่าระบบไม่มีบั๊กทุกกรณี สภาพแวดล้อมนี้เปิด Vercel URL โดยตรงถูก network proxy ปฏิเสธ การตรวจปล่อยขึ้นจริงจึงใช้ผล Vercel check ที่ผูกกับ commit บน GitHub แยกจากหลักฐาน browser ของ production build ในเครื่อง ไม่อ้างว่าได้เปิด browser ตรวจ production URL โดยตรงแล้ว
